# Designer: self-update vs what actually shipped

Owner asked for a **native Mac app** that, once downloaded, **updates itself**. Engineering must not invent a second install path. This note is a stop-and-report.

## What the owner signed

1. Every agent has the six native plugins (already in the Python package).
2. macOS packaging: `Universal.app` + `Universal.dmg` (`scripts/build_macos.sh`, `scripts/create_dmg.sh`, `universal desktop`).
3. Self-update from GitHub Releases (download the new `.dmg`, replace the app).
4. User data (memory, agent identities) survives replacing the `.app`.

The updater is only meaningful for **the packaged app**. A source zip / `pip install` / folder demo **cannot** apply that update (`apply` is frozen + Darwin only). Offering that zip as “the download” breaks the product.

## The problem (say this back)

The owner can now get a `.dmg`. **That app still cannot update itself** until you decide:

1. **Which GitHub repo is baked into the binary?** Today nothing is baked. Without `UNIVERSAL_UPDATE_REPO=owner/name` inside the frozen app, “check for updates” is a no-op. Candidate: `anthony-x507/Abaco-Universal-harnes-`.
2. **When does the app check?** Never / on launch (prompt only) / Settings button. Engineering will not auto-replace the app on launch without your sí.
3. **Where is the installed app?** Only `/Applications/Universal.app`, or “the running `.app` bundle path”? Homebrew-style copies break a hard-coded Applications path.
4. **Is the source zip retired?** If yes, remove it from Releases so nobody installs a tree that can never `--apply`.
5. **Signing?** Unsigned PyInstaller apps are second-class on modern macOS. Self-update that swaps the bundle will keep hitting Gatekeeper unless you add Developer ID + notarize (out of scope unless you say sí and provide certs).

## What engineering will not do until you answer

- Another “demo folder” or `pip` installer presented as the Mac product.
- A second factory, second registry, or plugin `.py` copies under Application Support as the update mechanism.
- Silent overwrite of `/Applications` on every launch.

User data already lives outside the `.app` (`Application Support/Universal`: memory, `registry.json`, plugin **manifest** only). Replacing the `.app` does not wipe agents. The missing piece is **the app knowing where to fetch the next `.dmg` and a human-facing apply step**.

## Ask the designer

One paragraph: default repo, check UX (launch prompt vs Settings), install path, retire the zip, signing yes/no. Then engineering wires **only** that. No new product slice.
