# UI Integration with Open‑Source ChatGPT/Codex Interface

This document explains how to use an open‑source ChatGPT/Codex‑style frontend (like LibreChat or Open WebUI) with the Aegis Agent Factory as the backend.

## Approach

We will connect an existing open‑source UI to our Factory via a REST API that follows the OpenAI API format. This allows us to reuse polished frontends without rebuilding the entire interface.

## Recommended Open‑Source UIs

| Project | Description | Why It Fits |
|---------|-------------|-------------|
| **LibreChat** | Fully featured ChatGPT clone (multi‑model, file upload, code interpreter, plugins) | Supports custom endpoints; can be extended with our backend |
| **Open WebUI** | Clean, fast, ChatGPT‑like UI; supports multiple backends via API | Easy to configure to call our Agent Factory API |
| **Chatbot UI** | Minimal React UI, very similar to ChatGPT | Lightweight, easy to modify |
| **Lobe Chat** | Modern, feature‑rich; supports plugins and multiple providers | Good plugin system; can be pointed to our API |

All are open source and self‑hostable. **LibreChat** is the primary reference because it already includes streaming, code highlighting, multi‑model support, and plugin architecture.

## Integration Architecture

Open‑Source UI (React) 
│  HTTP/WebSocket 
▼ 
Aegis Agent Factory (Python) 
├── Agent Manager (create/start/stop agents) 
├── Plugin Manager (shared plugin library) 
├── LLM Provider Manager (40+ models) 
└── Communication Manager (Telegram, etc.)


The UI calls REST API endpoints exposed by the Factory. The frontend remains independent and replaceable.

## API Endpoints to Expose

We will add a lightweight FastAPI service inside a new `api/` folder:

- `POST /v1/chat/completions` – OpenAI‑compatible chat endpoint (so many UIs work out of the box)
- `GET  /v1/agents` – list created agents
- `POST /v1/agents` – create a new agent (with template, model, plugins, comm channels)
- `POST /v1/agents/{id}/start` – start an agent
- `POST /v1/agents/{id}/stop` – stop an agent
- `GET  /v1/agents/{id}/status` – get agent status
- `POST /v1/agents/{id}/deploy` – deploy agent to GitHub
- `GET  /v1/status` – factory status (plugins, models, communication)

The chat endpoint follows the OpenAI API format, so any compatible UI can be pointed to `http://localhost:8000/v1` and work with minimal changes.

## Implementation Plan

1. Add `api/` folder with FastAPI app (`api/main.py`) that wraps the Agent Factory.
2. Create a Docker compose file that runs:
   - The open‑source UI (e.g., LibreChat) on port 3000.
   - Our FastAPI backend on port 8000.
3. Configure the UI to use our backend as its “OpenAI‑compatible” provider (set the API base URL).
4. Extend the UI (if needed) to show our unique features:
   - Right‑side panel with agent status, token usage, sandbox info.
   - Buttons for “Create Agent”, “Deploy to GitHub”, etc.
   - File tree and preview (for coding agents).

Since the UI is open source, we can fork it and add custom panels without rebuilding the core chat experience.
