1. Add Streaming Support to LLM Providers

We'll add a stream method to the OpenAICompatibleProvider base class, and use it in the API when available. This makes token‑by‑token streaming possible.

📁 Updated integrations/llm_providers.py (add stream method)

Add the following method to OpenAICompatibleProvider (and optionally to others, but we'll focus on OpenAI‑compatible):

class OpenAICompatibleProvider(BaseLLMProvider):
    # ... existing code ...

    def stream(self, messages, **kwargs):
        """Yield response tokens as they are generated."""
        import openai
        openai.api_key = self.api_key
        openai.api_base = self.base_url
        response = openai.ChatCompletion.create(
            model=self.model,
            messages=messages,
            stream=True,
            **kwargs
        )
        for chunk in response:
            if 'choices' in chunk:
                delta = chunk['choices'][0].get('delta', {})
                content = delta.get('content', '')
                if content:
                    yield content

For other providers (Anthropic, Google, etc.) we can add later; for now, the API will check if the provider has a stream method and use it; otherwise, fallback to simulating streaming with the full response.

Option A: Direct Provider Streaming Endpoint (simpler)

Create a new endpoint in chat.py that accepts a model and messages, gets the provider, and streams response using SSE. This gives immediate real streaming without modifying the Agent.

@router.post("/chat/stream")
async def chat_stream(request: ChatCompletionRequest):
    """Streams response directly from LLM provider."""
    provider_name = request.model.split('/')[0] if '/' in request.model else "openai"
    provider = get_llm(provider_name, model=request.model)
    # Convert messages to provider format if needed
    messages = [{"role": m.role, "content": m.content} for m in request.messages]
    # Define async generator that yields chunks
    async def generate():
        try:
            for token in provider.stream(messages, temperature=request.temperature):
                data = {
                    "id": f"chatcmpl-{uuid.uuid4().hex}",
                    "object": "chat.completion.chunk",
                    "created": int(time.time()),
                    "model": request.model,
                    "choices": [{"delta": {"content": token}, "index": 0, "finish_reason": None}],
                }
                yield f"data: {json.dumps(data)}\n\n"
                await asyncio.sleep(0)
            yield "data: [DONE]\n\n"
        except Exception as e:
            logger.error(f"Streaming error: {e}")
            yield f"data: {json.dumps({'error': str(e)})}\n\n"
    return StreamingResponse(generate(), media_type="text/event-stream")

Add the necessary import from integrations.llm_providers import get_llm.

This provides real streaming, and the UI can call this endpoint for live token display.

// Modify fetchJSON to show/hide activity automatically
async function fetchJSON(url, options = {}) {
    showActivity();
    try {
        const response = await fetch(url, {
            headers: { 'Content-Type': 'application/json' },
            ...options,
        });
        if (!response.ok) {
            const error = await response.text();
            throw new Error(error);
        }
        return response.json();
    } finally {
        hideActivity();
    }
}

4. Ensure Strong Wiring & Performance

To prevent lack of communication and slowness:

· The API runs with async FastAPI, so multiple requests are handled concurrently (unless the underlying Agent calls are blocking). To avoid blocking, we should run heavy LLM calls in a thread pool executor. 
· Add a thread pool executor in api/main.py:

from concurrent.futures import ThreadPoolExecutor
executor = ThreadPoolExecutor(max_workers=10)

# In chat endpoint, when calling agent.process_user_message, use executor:
loop = asyncio.get_event_loop()
response_text = await loop.run_in_executor(executor, agent.process_user_message, "api_user", last_user_message)

This keeps the event loop free. We'll update the non‑streaming endpoint accordingly.
